## Standing notes

- Pages and `/js/**` are served `Cache-Control: no-cache` (firebase.json) on purpose, so a deploy shows on the next reload; `styles.css` keeps normal caching because it is versioned with `?v=N`.
- There is no `@media print and (orientation: portrait)` rule on purpose: Chromium misfires it on landscape pages and it clipped every printed sheet.
- On /03 a tap in a beat that already has a note on another row REPLACES it (one note per beat); that is the requested behaviour.
- In 3/4 on /02, AI is hidden and five rhythm buttons are greyed on purpose. **[Updated 2026-10-07: Print and Scan now work in 3/4 — it has its own sheet, `kidseq:main5_34` (T-005).]**
- Scans on the full sequencer and /03 reproduce colouring cell for cell (off-beat notes allowed); only /02 snaps scans to the beat.
- Audio timing is deliberately indirect (2026-10-07): each step is placed in a slot on the audio clock 100 ms ahead, and the playhead, beat flash and note pulse fire up to 100 ms after the tick (`setTimeout`) so they land with the sound; `stop()` cancels them. That is not lag to "fix" — see CLAUDE.md "Audio placement". Every voice reads `_audioNow()`. **[Updated 2026-10-07: the lead is now 300 ms, not 100 — first step after Play 100 ms ahead, lessons stay at 100 ms; the visuals follow the same slots. See the next notes.]**
- `ensureAudioReady()` deliberately no longer rebuilds the AudioContext on idle (only a "running" context with a frozen clock, max 2 per page load). Re-adding the old >25 s idle rebuild reintroduces context churn, the prime suspect for the iPad's silent-until-reboot bug.
- `iosStartSilentVideo()` is keyed on `iPhone|iPad|iPod` in the user agent, which iPadOS Safari doesn't send by default (it reports a Mac), so it never runs on an iPad. Harmless; left as is.
- The audio lead is **300 ms on purpose** (`SCHED_LEAD_S`; `SCHED_START_S` 100 ms for the first step after Play/restart; lessons keep 100 ms). A debug-panel `min lead` of ~280 ms is healthy, not lag. A note placed less than 300 ms ahead of the playhead waits for the next pass — accepted trade-off. Not to be lowered without re-running the harness: 100 ms measurably dropped steps.
- The note swell is done with `Element.animate()` + cached literal keyframes (`pulseNoteBlock`), `.noteBlock` has a permanent `will-change: transform`, and the beat flash animates only `opacity` of `::before`/`::after` on `.beatBadge`. These look like odd ways to do a CSS pulse and are deliberate: the CSS versions (class toggle + `var()` keyframes, `background`/`box-shadow` animation) repainted on the main thread every step and starved the audio scheduler on slow devices. The old class path (`setBlockPulseVars`, `.noteBlock.playing`, `@keyframes swell`) stays as the fallback where `Element.animate` is missing — it is not dead code.
- `?audiodebug=1` expires 6 hours after it is opened (`AUDIO_DEBUG_TTL_MS`, 2026-10-07): the stored value is an expiry time, not `"1"`. Any old `"1"` (e.g. left on the owner's iPad) is cleared on the next load, so the iPad tests (T-006, T-010) start by opening `/?audiodebug=1` again, which their steps already say. A test running past 6 hours needs it reopened.
- 6/8 on /02 (2026-10-07) is deliberate in these ways: `tempo` still counts QUARTER notes, so at 120 the dotted-quarter beat (and the beat flash) runs at 80/min — the audio engine has no per-signature path; there is no 16th tool and no plain quarter tool in 6/8 (the set is 8ths-in-threes, long-short, dotted quarter, dotted half); tapping either note of a long-short deletes both (in 6/8 any sub-beat tap clears that beat's sub-beat notes); the `kidseq:main5_68` insets are identical to `kidseq:main5_34` because the two printed layouts measure the same, not because one was copied.
- The `stageScaled` touchmove guard (index.html, layout IIFE ~7356) deliberately cancels EVERY drag, every multi-finger move and Safari's `gesturestart`/`gesturechange` — including ones that start on a `<button>` — and exempts only text fields and scrollable overlays (2026-10-08). It looks heavy-handed; it is what stops iPad Safari sliding/zooming the page. A tap still clicks. Likewise `applyStageFit` deliberately sets `offX = offY = 0`: `#viewport` is already moved onto the visual viewport, so adding the offset again put the stage off the screen. Don't "restore" either.
- Rendering/animation cost cannot be measured in the Browser pane (frozen compositor: forced layout 30–45 ms even idle, ~127 phantom animations). Use headless Chrome over CDP with `Emulation.setCPUThrottlingRate`, as in `docs/handover/perf-harness/`. CPU throttling is a stand-in only; the iPad result is what counts.
- Audio self-reports (2026-10-09): the app writes its own audio-health records to Firestore `audioReports` (create-only rule, `{v:1, report:<JSON string ≤ 9000>, createdAt}`, no user id; UA + audio state only). Triggers: refresh/reopen soon after playing, detected faults, immediate `now:*` reports from a failing page, glitch reports, and a summary per play session. This is deliberate data collection approved by the owner, not leftover debugging.
- Synth drums are rendered by temporarily pointing the globals `audioCtx`/`drumBus` at an OfflineAudioContext for ONE synchronous `play*` call (`renderSynthDrumKit`), and `trackNode` returns early while `_renderingOffline`. It looks hacky; it is the way to reuse the drum code unchanged and is safe because nothing else can run during a synchronous call.
- Drum choke (max 2 overlapping hits of the same drum, 1 in light mode), melodic voice cap (32/16/8) and the automatic light mode are deliberate load control for school iPads, not bugs. Stolen voices are also disconnected after their fade because `stop()` refuses a second call.
- The volume fader can reach silence on purpose (owner 2026-10-09 declined a floor). The dead-output self-repair skips when the fader is at zero.
- Guests see a greyed AI button whose box says "Sign up to make AI songs" and highlights the free Member plan, although AI is Pro-only — owner said this is fine (2026-10-09).
- Pressing Play in one tab makes every other tab of the app stop and suspend its AudioContext (BroadcastChannel `kidseq-audio`) — deliberate; iOS lets one page hold the audio.
